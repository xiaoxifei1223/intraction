# 痛点挖掘（桌面研究版）

你不是访谈员，而是**证据调查员**。

用户只会给你粗糙的初始信息——"我认为的目标客户是……""场景大概是……""我有个产品想法……"。这些**全部是待验证的假设，证据权重最低**。你的工作是：自主搜索公开信息，从真实用户留下的行为痕迹里找出痛点，然后**验证或推翻**用户的初始假设。

```text
用户初始输入（假设） ──► [本 skill] 桌面研究 ──► 痛点假设清单 ──► 交换模型设计 ──► 落地产品设计
```

**唯一成功标准**：清单里每一条结论，都能点开一个链接，看到某个真实用户**做过什么**，而不只是**说过什么**。

---

## 0. 定位与硬边界

### 0.1 输入 / 输出

| 项 | 内容 |
|---|---|
| 输入 | 用户自述的目标客户、使用情境、产品想法、已有判断（全部按假设处理） |
| 输出 | 《痛点假设清单》：JTBD 描述、痛点假设、证据摘录与链接、证据强度、可量化代价、反证情况、证伪条件 |
| 附带 | 《不可信信号清单》《与初始假设对账表》《桌面研究证据缺口》《搜索日志》 |

### 0.2 五条硬边界（违反即失败）

1. **不设计解决方案**。输出里不出现功能、按钮、页面、算法、定价、产品名。用户的产品想法只能用来生成搜索词，不能进入结论，也不能被评价好坏。
2. **不评估商业价值**。不算市场规模、ROI、优先级、竞争格局。价值判断属于下游。
3. **不把用户输入当事实**。用户说"目标客户是 25–35 岁女性"，这句话本身不是证据，只是待验证假设；用户是利益相关方，其判断天然有偏。
4. **不编造来源**。每一条引用必须是逐字摘录 + 可点击链接 + 采集日期。搜不到就写"未找到"，绝不允许用常识、经验或"一般来说"补位，也不允许用 agent 自身或用户的经验轶事当证据。
5. **不是访谈工具**。本 skill 不产出访谈提纲、不要求用户去做访谈、不假装访谈已完成。它只做公开信息桌面研究。

### 0.3 什么时候不该用本 skill

- 需要用户内部数据、线下行为、B 端内部流程 → 桌面研究覆盖不了，只能标"证据缺口"，不要硬编。
- 需要验证一个已有方案好不好用 → 可用性测试/增长实验，不是痛点挖掘。
- 需要判断"这门生意值不值得做" → 商业分析，本 skill 不覆盖。
- 需要访谈执行 → 另有一套访谈方法；本 skill 只消费公开语料。

### 0.4 执行方式：自主研究，不向用户要资料

1. **自己找来源**。不要求用户提供链接、截图、数据；用户只负责初始输入与最终确认。
2. **每轮搜索后更新状态**。假设状态只允许在"待验证 / 证实 / 推翻 / 部分成立 / 证据不足"之间流转，且每次流转要有新证据或新反证。
3. **默认研究预算**：每条假设 ≤90 分钟、≤15 次查询。超时就标"证据不足"并进入缺口表，**不允许用常识补写**。
4. **只在两个时点与用户交互**：开始时澄清输入（≤3 个问题），结束时交付清单与对账结果。中途不反复请示。

## 1. 理论底座：怎么用在"网上言论"上

| 来源 | 取用的命题 | 桌面研究的落点 |
|---|---|---|
| **俞军《产品方法论》** | 用户不是自然人，而是需求的集合；一个人只在某个情境下的某类需求上才是你的用户 | 不按人口属性圈人，按"任务 × 情境"圈证据 |
| | 需求五问：本质、演变、影响因素、行为出口（+ 本 skill 增补的"边界"） | S1 拆假设、S2 造搜索词、S5 写假设 |
| | 用户价值 = 新体验 − 旧体验 − 替换成本；"用户不换方案"本身是信息 | S5 替代方案、S6 反证 |
| **The Mom Test** | 只有具体行为、过去的解决方式、已付出的代价才是可信信号；"喜欢"不是证据 | S3 采集、S4 甄别 |
| | 三类坏数据：compliments / fluff / ideas | S4 丢弃清单 |
| | 承诺与推进：愿意付出时间/声誉/金钱才算数 | S8 证据分级 |
| **JTBD** | 痛点必须锚定：什么情境下、想完成什么任务、现有方案卡在哪 | S5 转写 |
| | 保留反例（含未改变做法的人）与"已解决"的证据 | S6 反证搜索 |
| **梁宁《产品思维 30 讲》**（补充） | 痛点是恐惧，痒点是虚拟自我，爽点是即时满足 | S5 判定、S9 概念校准 |
| **徐锋《有效需求分析》**（补充） | 需求 = 预期与现状的差距；方案级 → 问题级 → 人性级 | S4 降权功能点评、S5 写假设 |

### 1.1 操作性定义：什么才算"痛点"

> **痛点 = 任务 × 情境 × 结构性障碍 × 不可接受代价**

四要素缺一不可，缺一个就只能降级：

| 类型 | 判定 | 网上典型表达 | 处理 |
|---|---|---|---|
| **抱怨** | 只有情绪，没有任务与事件 | "真的服了，太坑了" | 追事件与代价，可能升级 |
| **痒点** | 现状可完成，只是不够好 | "要是界面再好看点就好了" | 不是痛点，标记后放下 |
| **爽点** | 追求即时满足 | "一键生成也太爽了" | 不是痛点，标记后放下 |
| **伪需求** | 嘴上要，但没有行为与代价 | "求一个能自动搞定一切的 App" | 丢弃或降权为线索 |
| **痛点** | 任务明确、情境可回放、障碍结构性、代价可量化 | "上个月对账对了 6 小时，最后一笔还得手工找" | 进入清单 |

**"结构性"的三个检验**（必须同时满足）：

1. **可重复**：同类用户在同一情境下反复遇到（多帖/多人提到，且不是一次性事故）。
2. **非个人**：不因某个人更努力、更熟练而消失；换个人仍会卡住。
3. **绕不过**：现有替代方案能缓解但不能消除；用户已经在为绕开它付出成本。

> **与梁宁的"痛点=恐惧"如何共存**：恐惧是痛点的**情绪显影**，不是痛点本身。帖子里写"我怕搞砸""不敢跟老板说"是重要线索，但必须还原到"哪次事件、卡在哪一步、付出了什么"才能进清单。只记录情绪而不还原任务与代价，等于用情绪代替证据。

### 1.2 网上的"说的 vs 做的"：五条判定

一条网上言论，同时满足 **≥3 条**才算**行为证据**，否则归入**态度表达**：

| # | 判定 | 通过例子 | 不通过例子 |
|---|---|---|---|
| 1 | **第一人称**：本人在讲自己的事 | "我上个月……" | "我朋友说……""大家都……" |
| 2 | **已发生**：过去时、有具体时间 | "上周三对账时……" | "如果有个工具……""我一般会……" |
| 3 | **具体动作**：用了什么工具/怎么做的 | "导出 CSV 再 VLOOKUP" | "体验很差" |
| 4 | **有数量**：时间/金额/次数/单量 | "4 个平台对了 6 小时" | "弄了好久" |
| 5 | **有结果**：最后怎么了 | "还是错了一笔，被财务退回来" | "希望有人解决" |

> 记住：**"喜欢"不是证据，"用了并且付出了代价"才是。** 夸和骂都只是情绪温度计，不是行为记录。

### 1.3 需求五问（作为搜索与分析框架）

| # | 问题 | 桌面研究里的具体做法 | 不合格信号 |
|---|---|---|---|
| 1 | 需求的本质是什么？ | 用户想完成的任务是什么？功能型/情感型/社会型？ | 只在讨论功能好坏 |
| 2 | 需求如何演变？ | 搜"以前怎么做的""后来换成了什么" | 只有当下抱怨，无演变 |
| 3 | 受什么因素影响？ | 哪些情境更强？换平台/规模/角色，说法变不变？ | 无法指出任何情境差异 |
| 4 | 行为出口在哪里？ | 他现在实际用什么替代方案？付出什么？ | 只有愿望，没有替代行为 |
| 5 | 边界在哪里？ | 哪类用户/情境下这个问题不成立？ | 搜不到任何反例 |

> 前四问沿用给定框架；第五问是本 skill 为"可证伪"增补的。答不出第五问的假设，不允许进清单。

## 2. 研究边界与输入预检

正式开搜前，先固定四件事，写进《研究范围声明》：

| 项 | 默认设置 | 说明 |
|---|---|---|
| **时间窗** | 近 24 个月优先，超过 36 个月的帖子降权 | 产品与平台规则会变，旧痛点可能已被解决 |
| **地域/语言** | 中文为主；目标市场在海外则加英文 | 只搜一种语言会漏掉关键证据 |
| **平台范围** | 至少覆盖 3 类信息源（见 S2） | 单一平台必然有偏差 |
| **排除项** | 营销软文、水军、竞品黑稿、AI 批量内容 | 采到就记入《不可信信号清单》并说明理由 |

**输入不足怎么办**：不要停下来等用户补信息。先用用户给的任何一句话做一轮**探索性搜索**（30 分钟内），带着"我搜到了什么、还缺什么"再向用户提 1–3 个澄清问题。禁止在没有任何证据时直接产出清单。

## 3. 九步工作流

> 每一步固定输出：**操作 → 产出物 → 完成判据 → 常见错误**。做完一步再进下一步。
>
> 下文 S1–S9 即 Step 1–Step 9。
>
> 两种模式：**快速模式（2–3 小时）**：S1→S2→S3→S4→S5→S6（仅核心假设）；**完整模式**：S1–S9 全跑。

---

### Step 1 · 初始假设登记

**目的**：把用户给的每句话拆成可验证/可推翻的假设，并明确本研究的验证目标。

**操作**

1. **逐条拆解**用户输入，按类型编号：`U-01` 起。
   - **目标客户假设**：用户认为谁有这个问题。
   - **情境假设**：用户认为问题在什么条件下发生。
   - **产品想法假设**：用户想做的方案（用于生成搜索词 + 对照现有方案覆盖度，不评价方案好坏）。
   - **痛点判断假设**：用户认为"痛在哪里、有多痛"。
   - **因果假设**：用户认为"为什么现有方案不行"。
2. **统一标注**：`来源 = 用户自述（利益相关方）`；`证据权重 = 最低`；`当前状态 = 待验证`。
3. **把每条假设翻译成一个验证问题**：这条假设被什么证据证实？被什么证据推翻？写不出来，说明假设不可验证，要求用户补充。
4. **声明验证目标**：本次研究要回答的 3–5 个问题，按优先级排序。产品想法不进入验证目标，只进入搜索关键词。

**产出物**：《初始假设登记表》

| ID | 类型 | 用户原话/转述 | 验证问题 | 可能推翻它的证据 | 状态 |
|---|---|---|---|---|---|
| U-01 | 目标客户 | "中小电商财务" | 真实发帖抱怨对账的人，岗位是不是财务？ | 发帖者多为运营/老板 | 待验证 |
| U-02 | 情境 | "每月月结" | 抱怨是否集中在月初？ | 抱怨集中在日常对账 | 待验证 |
| U-03 | 产品想法 | "想做个自动对账工具" | 现有方案是否已满足它想解决的问题？ | 竞品已完全覆盖且用户满意 | 待验证 |
| U-04 | 因果假设 | "平台数据不互通，只能手工" | 卡点是否真是数据不互通？ | 卡点在流程或权限，而非数据 | 待验证 |

**完成判据**：每条假设都有"可能推翻它的证据"；验证目标 ≤5 条；产品想法只作对照，不单独列为验证目标。

**常见错误**：把用户的话直接写成研究结论；把产品想法当成待验证的痛点；假设写成"用户需要更好的 X"这种无法推翻的句式。

---

### Step 2 · 搜索计划制定

**目的**：让搜索可复现，而不是随手搜几个词。

**操作**

1. **选信息源类型**：每条假设至少覆盖 2 类来源，整体至少 3 类。

| 信息源类型 | 平台示例 | 能提供什么 | 主要陷阱 |
|---|---|---|---|
| 垂直社区/论坛 | 行业论坛、贴吧、豆瓣小组、Reddit、专业 BBS | 长文、完整 workaround、同行黑话 | 意见领袖偏差、老帖 |
| 应用商店评价 | App Store、Google Play、华为/小米商店 | 使用中的具体摩擦、版本问题 | 刷评、情绪化短评 |
| 电商评价 | 淘宝/京东/拼多多、Amazon | 购买后的真实使用与退货原因 | 好评返现、刷单 |
| 投诉平台 | 黑猫投诉、12315、Trustpilot、BBB | 完整事件链、金额与处理结果 | 单方陈述、极端案例 |
| 问答社区 | 知乎、Quora、Stack Exchange | "怎么做 X"背后的任务与替代方案 | 软广、答非所问 |
| 社交媒体 | 微博、小红书、抖音评论、X、脉脉 | 高频情绪、场景碎片、行业吐槽 | 算法放大、段子化 |
| 竞品官方渠道 | 更新日志、帮助中心、反馈看板、客服话术 | 官方承认的问题、已解决/未解决 | 官方叙事、选择性披露 |
| 行业报告/媒体 | 研究机构、垂直媒体、深度报道 | 背景、术语、规模边界 | 宏观，不能当痛点证据 |
| 搜索趋势 | Google Trends、百度指数、微信指数 | 需求存在性与季节性 | 只有相对热度，无因果 |

2. **为每条假设 × 每个来源写 3–5 个具体关键词**。关键词按公式组合：

> **任务词 + 情境词 + 行为词 + 替代方案词 / 竞品名（+ 反证词）**

示例（对账假设）：
- 行为词：`用了` `试过` `后来` `只能` `每次` `花了` `折腾` `放弃` `换成` `退款`
- 情境词：`月结` `月初` `对账` `爆单`
- 替代词：`Excel` `VLOOKUP` `手工` `代账`
- 反证词：`够用` `解决了` `没必要` `习惯了`

3. **加搜索语法**：`site:` 限定平台、引号锁定短语、`-` 排除营销词、时间筛选。
4. **排优先级**：先行为词、先垂直社区与投诉平台；情绪词只用来发现线索，不直接当证据。
5. **建《搜索日志》**，每查一次记一行。

**产出物**：《搜索计划表》+《搜索日志》

| 假设 | 子问题 | 来源 | 关键词（3–5） | 预期证据形态 | 优先级 |
|---|---|---|---|---|---|
| U-01 | 抱怨者是谁 | 黑猫投诉 | 对账 平台 账单 出错 人工 | 含岗位与流程的投诉 | P0 |
| U-02 | 是否集中在月初 | 知乎 | 电商 财务 月结 加班 对账 | 时间线描述 | P0 |
| U-04 | 现有方案卡点 | 竞品反馈看板 | 对账 同步 失败 导入 | 官方承认的缺陷 | P1 |

**完成判据**：任何人拿着这张表，能复现同样的搜索；每条假设至少 2 类来源、每源 3–5 个词。

**常见错误**：只搜支持自己判断的词；只用中文；只搜社交媒体（情绪多、行为少）；没有反证词。

### Step 3 · 用户原声采集

**目的**：建立可回溯的证据库，而不是收集一堆印象。

**操作**

1. **打开原帖读全文**，不看标题和摘要就摘录视为无效。
2. **每条摘录一个编号** `E-01` 起，按固定字段记录：

| 字段 | 要求 |
|---|---|
| 来源链接 | 可点击的原始 URL（不是转载、不是截图） |
| 平台 | 具体站点/板块 |
| 采集日期 | YYYY-MM-DD |
| 用户标识 | 匿名化（如 U-A7），同一人多帖用同一标识 |
| 原文摘录 | 逐字，≤200 字，不改写、不总结 |
| 类型初判 | 行为证据 / 态度表达 |
| 情境要素 | 时间、角色、工具、触发事件（有就记） |
| 代价线索 | 时间/金额/次数/返工/情绪（有就记） |

3. **来源质量排序**（用于定优先级）：一手原帖 > 原帖评论区 > 个人博客/专栏 > 转载 > 媒体总结 > 行业报告（只作背景）。同一事实优先采一手；含具体数字的长文 > 含完整经过的中评 > 短差评 > 一句话吐槽。
4. **停止条件**：连续 2 轮新查询不再出现新证据类型，或每个假设已有 ≥10 条候选摘录，即停止该方向。
5. **绝不改写**：保留错别字、口语、黑话。改写会让证据失去可核验性。

**产出物**：《证据库》（E 表）

**示例（占位链接，仅示范格式）**

```text
E-07 | https://example.com/forum/thread-001 | 某电商论坛 | 2026-10-20
用户：U-A7（卖家，3 年）
原文："月初四个平台对账，光是把账单导出来整理就两个晚上，VLOOKUP 还老对不上，
      上个月有一笔差异找了三天，最后发现是平台扣费没同步。"
类型：行为证据（第一人称、有动作、有时间、有结果）

代价：两个晚上 + 3 天排查 1 笔差异
```

**完成判据**：每条摘录都能点开原链接；有链接、日期、原文、类型四要素；无转述代替原文。

**常见错误**：只截一句话导致断章取义；把转载/媒体二手当原帖；把"求推荐"当行为；收藏了但没记日期。

### Step 4 · 信号甄别（Mom Test 标准）

**目的**：只让行为证据进入痛点分析，态度表达单独归档、降权。

**操作**

1. **逐条打分**：用 §1.2 的五条判定，≥3 条通过 → 行为证据；≤2 条 → 态度表达。
2. **态度表达单独建库**，标注：`弱信号，仅作线索，用于指引下一轮搜索，不作为结论`。
3. **去重计数**：同一用户多帖算 1 个独立来源；同一内容被多平台转载算 1 条。
4. **丢弃或降权以下模式**（写进《不可信信号清单》）：

| 模式 | 为什么不可信 | 处理 |
|---|---|---|
| 假设性愿望（"要是有个 X 就好了"） | 没有发生的行为与代价 | 降权为线索 |
| 功能点评（"这个功能不错/垃圾"） | 是评价，不是使用经过 | 降权 |
| 纯情绪（"服了""救命"） | 有情绪，无任务与代价 | 只作线索 |
| 求推荐/求资源（"有没有人推荐"） | 说明在找方案，但未证明痛点 | 线索级 |
| 二手转述（"我朋友说""同事都"） | 非本人行为 | 不计入 n |
| 营销软文/引流帖 | 利益驱动 | 丢弃 |
| 竞品黑稿/水军 | 利益驱动 | 丢弃 |
| 段子/玩梗 | 情绪被放大、事实被压缩 | 丢弃 |
| AI 批量生成内容 | 无真实经历 | 丢弃 |
| 只有态度没有事件的"好评/差评" | 褒贬都不构成证据 | 降权 |

5. **严禁"有人骂=有痛点"**。骂只证明情绪，不证明任务、情境、代价。必须继续找"他到底做了什么、付出了什么"。

**产出物**：《甄别表》：E-ID | 判定 | 通过几条判定 | 保留/降权/丢弃 | 理由

**完成判据**：每条摘录都有判定与理由；被丢弃的能归入上表某一模式；态度表达没有混进假设。

**常见错误**：把点赞数/评论数当证据强度；把一条高赞情绪帖当普遍现象；把"求推荐"当需求；对差评照单全收。

### Step 5 · 痛点假设化

**目的**：把通过甄别的行为证据转成可证伪的假设。

**操作**

1. **先写 JTBD 句式**（每条一个任务）：

> **当【情境】时，用户想要【完成任务】，以便【期望结果】，但现有方案在【卡点】出了问题。**

2. **再写痛点假设**：

> **【用户群】在【情境】下因【结构性障碍】无法完成【任务】，目前用【替代方案】应对，付出了【可量化代价】。**

3. **障碍归类**（七类，必须对上一类）：

| 障碍类型 | 定义 | 判定问句 | 证据里长什么样 |
|---|---|---|---|
| 信息 | 不知道、不会判断、信息不对称 | 缺哪条信息？ | "不知道怎么核对字段" |
| 能力 | 技能/经验不足 | 换熟手能否解决？ | "不会写公式" |
| 资源 | 钱、时间、人力不够 | 加钱/加人能否解决？ | "小团队没人专职做" |
| 制度 | 流程、合规、权限 | 是否被规则卡住？ | "必须走纸质审批" |
| 协作 | 多方交接、责任不清 | 是否卡在"等别人"？ | "差异要运营逐笔确认" |
| 心理 | 恐惧、羞耻、信任 | 是否怕出错而不敢行动？ | "怕报错被老板骂" |
| 工具/环境 | 现有工具缺失或不匹配 | 有工具但用不了？ | "平台导出格式不一致" |

4. **量化代价**：时间 / 金钱 / 机会 / 风险与返工 / 情绪关系。桌面研究只能从原话里取数；**取不到就写"原话未给数"，再给一个标明方法的估算区间**，例如"2 个晚上 ≈ 8–10 小时（按每晚 4–5 小时估）"。估算必须标注"估算"，不能冒充事实。
5. **一句一任务、一条假设一个主障碍**；有主次时标"主障碍/次障碍"。
6. **写边界**：适用哪类用户、哪种情境；不适用谁。

**产出物**：H-01、H-02……每条挂 1–3 条 E-ID。

**完成判据**：能写出证伪条件；障碍可重复、非个人、绕不过；代价有数字或标明方法的估算；无方案词。

**常见错误**：把帖子里的方案当任务；一条假设塞两个障碍；代价写"体验差"；把单条极端帖写成全体用户。

### Step 6 · 反证搜索（关键步骤）

**目的**：主动攻击自己的假设，避免只搜到支持性证据。

**操作**：对每条假设，至少完成 **2 类反证搜索**，并记录查询与结果。

| 反证类型 | 要问的问题 | 搜索词示例 | 结果处理 |
|---|---|---|---|
| **普遍性反证** | 是不是只有极少数人？ | `对账 没遇到` `挺好的` `不觉得` | 反例多 → 收窄用户群或降级 |
| **已解决反证** | 现有方案是不是已经解决了？ | `平台 自带 对账` `ERP 自动` `新版 已修复` | 已解决 → 标注"窗口已关闭" |
| **代价可接受反证** | 用户是不是其实能忍？ | `习惯了` `忍忍` `免费版够用` | 能忍 → 降为痒点 |
| **替代解释** | 是不是别的原因？ | `太贵` `不会用` `懒得学` `规则变` | 换解释 → 改障碍类型或降级 |
| **时间反证** | 是不是旧问题已被修复？ | `2025 更新` `现在 好了` | 已修复 → 标注时间边界 |

**处理规则**：

- 发现反证 → 先下调置信度，再判断是"假设错"还是"边界窄"。
- 反证集中在某类用户 → 把它写成边界条件，而不是删掉证据。
- 反证证明窗口已关闭（竞品已解决/平台已修）→ 假设降级为"历史痛点"，不进主清单。

**产出物**：《反证记录表》：H-ID | 反证类型 | 查询词 | 结果 | 对假设的影响

**完成判据**：每条假设至少 2 类反证查询有记录；每条都能回答"最可能错在哪"；没有一条假设只有支持证据。

**常见错误**：反证搜索只走形式（搜索词仍含支持性词汇）；找到反例就删假设而不看边界；把"没人抱怨"当成"没有问题"（也可能只是没搜到）。

### Step 7 · 与用户初始假设对账

**目的**：逐条回答"用户的判断被证实、推翻、部分成立，还是证据不足"。

**操作**

1. 对每条 `U-` 假设给判定：**证实 / 推翻 / 部分成立 / 证据不足**。
2. **目标客户一致性检查**：用户认为的目标客户，与实际发帖人群是否一致？不一致时要写清"真正出现痛点的是谁、差在哪"。
3. **产品想法检查**：用户想做的方案，是否已经被现有方案很好满足？只写"现有方案满足到什么程度"，不评价用户方案好坏。
4. 判定必须附证据链接，不接受"综合来看"。

**产出物**：《对账表》

| U-ID | 用户初始假设 | 判定 | 关键证据 | 差异/边界说明 |
|---|---|---|---|---|
| U-01 | 目标客户=财务 | 部分成立 | E-07、E-12 | 抱怨者以"运营兼财务"的小团队为主，纯财务岗多在 20 人以上团队 |
| U-02 | 痛点在月结 | 证实 | E-07、E-15 | 集中在每月 1–5 日 |
| U-03 | 产品想法：自动对账 | 部分成立 | E-07、E-12 | 现有工具只覆盖单平台，跨平台仍需手工；未评价方案本身 |
| U-04 | 现有方案不够 | 证据不足 | — | 未找到竞品更新日志，无法判断是否已解决 |

**完成判据**：每条 U- 都有判定与链接；目标客户不一致处已写明；判定为"证据不足"的已进入缺口清单。

**常见错误**：为了迎合用户把"部分成立"写成"证实"；只对账痛点不对账目标客户；把"没搜到"写成"不存在"。

### Step 8 · 证据分级与缺口标注

**目的**：让每条假设知道自己有多可信，以及桌面研究到哪里为止。

**操作**

1. **打证据等级**（取最低可得级别，不取平均）：

| 等级 | 定义 | 数量门槛 | 能否进主清单 |
|---|---|---|---|
| **A 多源行为证据** | 多个独立用户的具体行为与代价 | ≥3 个独立用户、≥2 类平台 | 可以 |
| **B 单源行为证据** | 有具体行为细节，但来源单一或样本少 | 1–2 个独立用户，或单一平台 | 可以，须标"待扩样" |
| **C 仅间接自述** | 二手转述、媒体案例、他人描述 | 无第一人称行为 | 只能进"待验证线索" |
| **D 推断** | 你从情绪、语境、评论互动里推断 | — | 不能进清单正文 |

2. **评级规则**：
   - 同一假设多条证据时**取最低级别**。
   - C 级必须注明"非本人行为"；D 级只能出现在《待验证线索》。
   - A 级必须写清"哪几个独立用户、哪几个平台"。
3. **标证据缺口**（桌面研究无法解决的，诚实写出来，不要求用户立刻补）：

| 缺口类型 | 桌面研究为什么补不上 | 需要什么实地验证 |
|---|---|---|
| 真实频率与规模 | 只有发帖的人可见，沉默大多数不可见 | 用户行为日志、抽样问卷 |
| 未发声用户 | 满意/无感的人很少发帖 | 代表性样本访谈 |
| 线下/私下行为 | 不发生在公开平台 | 现场观察、影子跟踪 |
| B 端内部流程 | 涉密、不在公网 | 企业内部访谈、流程走查 |
| 因果性 | 相关不等于因果 | 对照实验、A/B 测试 |
| 支付意愿 | 网上说的价格不是真实成交 | 预售、定金、真实报价测试 |

**产出物**：假设卡上的等级 +《证据缺口表》

**完成判据**：每条假设有等级与依据；C/D 级没有混进主清单；缺口写清"缺什么、为什么缺、需要什么方法"。

**常见错误**：把 3 条同一帖的转述当 3 个独立来源；把媒体案例当 A 级；用"行业普遍如此"补齐缺口。

### Step 9 · 反偏差审查

**目的**：在交付前系统性攻击自己的研究过程。

**操作**：逐项回答，每项要有具体答案，不能写"无"。

| # | 偏差 | 检测问句 | 修正动作 |
|---|---|---|---|
| 1 | **可得性偏差** | 我是不是只采信"搜得到的"？沉默的大多数在哪？ | 主动搜"满意/没需求/已解决"证据 |
| 2 | **确认偏误** | 我的搜索词是不是只含支持性词汇？ | 每条假设补 2 条反向词查询 |
| 3 | **单条高情绪当普遍** | 这条结论有几个独立用户？ | 标 n；n=1 只能作线索 |
| 4 | **平台算法放大** | 热帖是不是被推荐的极端案例？ | 跨平台交叉验证 |
| 5 | **幸存者偏差** | 我是不是只看抱怨者/只看好评者？ | 主动找中性、满意、放弃的用户 |
| 6 | **水军/营销内容** | 这账号/这措辞像不像软文？ | 查账号历史、多平台一致性 |
| 7 | **时间衰减** | 证据是不是来自 2 年前？ | 用时间窗过滤，旧帖降权 |
| 8 | **语境缺失** | 我是不是只截了一段？ | 读全文与上下文，必要时读评论区 |
| 9 | **转述偏差** | 这是本人原话还是媒体总结？ | 回溯原始出处 |
| 10 | **语言/地域偏差** | 我只搜了中文吗？ | 补英文/目标市场语言 |

**红队三问**（每条假设都要答）：

1. 这条假设**最可能错在哪**？
2. **谁会不同意**它？他的理由是什么？
3. 看到什么证据，我会**立刻放弃**它？

**产出物**：《偏差审查记录》

**完成判据**：10 项都有具体答案；每条假设有反例或"未找到反例"的说明；没有一条假设只有支持证据。

**常见错误**：审查走过场；把反例删掉以求"结论干净"；用"我认为"回答检测问句。

## 6. 常见失败模式

| 症状 | 根因 | 纠正 |
|---|---|---|
| 清单像"网上都在骂 X" | 把情绪当证据 | 回 S4，只留行为证据 |
| 每条都"很普遍" | 没有 n 与平台数 | 回 S8，标注独立用户数 |
| 证据全是同一平台 | 来源单一 | 补 2 类来源，交叉验证 |
| 结论正好印证用户想法 | 确认偏误 | 回 S6，补反向词搜索 |
| 引用了但点不开 | 记录了转载/截图 | 回 S3，回溯原帖 |
| 假设无法被推翻 | 写成了结论 | 加证伪条件与阈值 |
| 用"行业经验"补缺口 | 越界 | 回 S8，写进缺口表 |
| 产品想法混进结论 | 方案先行 | 回 S5，删所有方案词 |
| 只有 1 条高赞帖支撑 | 幸存者/算法放大 | 扩样，跨平台验证 |
| 对账在迎合用户 | 利益相关压力 | 按证据判，部分成立就写部分成立 |

### E. 术语表

| 术语 | 定义 | 检验方式 |
|---|---|---|
| 任务 Task | 用户想取得的进展，独立、可暂停、可汇报 | 换个人也能判断完成没有 |
| 情境 Situation | 触发 + 时间 + 场所/工具 + 约束 | 能回放到某一次具体发生 |
| 结构性障碍 Structural Blocker | 可重复、非个人、绕不过的缺口 | 三个检验全过 |
| 替代方案 Workaround | 用户现在实际使用的办法 | 能从原话里指出具体工具与动作 |
| 代价 Cost | 为绕开障碍付出的时间/钱/机会/风险/情绪 | 有原话数字或标明方法的估算 |
| 行为证据 Behavioral Evidence | 第一人称、已发生、有动作/数量/结果 | 五条判定 ≥3 条通过 |
| 态度表达 Attitude | 愿望、评价、情绪、未来时 | 五条判定 ≤2 条通过 |
| 独立来源 Independent Source | 不同用户/不同账号 | 同人多帖算 1 |
| 证据强度 Evidence Level | A 多源行为 / B 单源行为 / C 间接自述 / D 推断 | 取最低级别 |
| 证伪条件 Falsification Condition | 能推翻假设的可观察结果 | 二值可判、有阈值 |
| 坏数据 Bad Data | 夸奖、空话、点子、情绪、营销内容 | 按 §4.3 处理 |

---

> **最后自查一句话**：如果一条结论写成"网上很多人都有这个痛点"，它就不是结论，是印象。合格的结论，必须能点开链接，看到某个具体的人，在某个具体情境里，做了什么、付出了什么。
